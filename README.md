# موتورهای برنامه‌ریزی مطالعاتی ماز و رتبه‌لند

این مخزن راهنماهای قابل‌انتقال برای ایجنت فراهم می‌کند تا با دریافت **تاریخ/بازه، بودجهٔ آزمون ماز، کتاب‌های درسی و وضعیت داوطلب**، برنامهٔ مطالعاتی قابل‌اجرا تولید کند.

سه موتور مستقل وجود دارد:

- **فرمول سادهٔ جدید:** از بودجهٔ رسمی ماز استفاده می‌کند، اما با جلسه‌های ۷۵دقیقه‌ای، بافر واقعی، تعداد تست وابسته به تازه یا مروری بودن مطلب و چهار ساعت نهایی، برنامه را به‌شکل عددی و سرراست می‌سازد؛
- **رتبه‌لند اصلاح‌شده:** هستهٔ استاندارد ۴۷ ساعت/۴۹۵ تست را حفظ می‌کند، ولی تحلیل تست، ترتیب یادگیری و کنترل امکان‌پذیری را اصلاح می‌کند؛
- **روش ماز:** از برنامه‌های مطالعاتی واقعی ماز مهندسی معکوس شده و ظرفیت‌محور است؛ اعداد ثابت رتبه‌لند قانون ماز محسوب نمی‌شوند.

## نقطهٔ شروع

### برای ایجنت

1. [`AGENTS.md`](AGENTS.md) را بخوان.
2. موتور درخواست را انتخاب کن:
   - [`SIMPLE_PLANNING_FORMULA.md`](SIMPLE_PLANNING_FORMULA.md) برای فرمول سادهٔ جدید؛
   - [`RANKLAND_PLANNING_PLAYBOOK.md`](RANKLAND_PLANNING_PLAYBOOK.md) برای فرمول اصلی اصلاح‌شدهٔ رتبه‌لند؛
   - [`MAZ_PLANNING_PLAYBOOK.md`](MAZ_PLANNING_PLAYBOOK.md) برای روش ماز.
3. برای شناخت تفاوت دو روش قدیمی‌تر، [`PROGRAM_COMPARISON.md`](PROGRAM_COMPARISON.md) را ببین.
4. برای قواعد مستندِ زنگ ۷۵دقیقه‌ای، برنامهٔ حجمی ـ زمانی، مرحله‌بندی تست و دو روز پیش از آزمون، [`VOLUMETRIC_PLANNING_FORMULA.md`](VOLUMETRIC_PLANNING_FORMULA.md) را بخوان.
5. در مسیر ماز/ترکیبی، ورودی را با [`examples/REQUEST_TEMPLATE.yaml`](examples/REQUEST_TEMPLATE.yaml) دریافت کن.

### برای کاربر

برای فرمول سادهٔ جدید:

```text
طبق AGENTS.md و SIMPLE_PLANNING_FORMULA.md برای آزمون من برنامه بساز.
بودجهٔ رسمی را کنترل کن، زمان را به جلسه‌های ۷۵دقیقه‌ای تبدیل کن، چهار ساعت نهایی و زمان جبرانی را کنار بگذار و تعداد تست را براساس تازه یا مروری بودن مطلب تعیین کن.
```

برای فرمول اصلی اصلاح‌شده:

```text
طبق AGENTS.md و RANKLAND_PLANNING_PLAYBOOK.md برای آزمون من برنامه بساز.
هستهٔ ۴۷ ساعت/۴۹۵ تست را حفظ کن، بودجه و صفحات کتاب را کنترل کن و امکان حل و تحلیل هر باکس را بسنج.
```

برای روش ماز:

```text
طبق AGENTS.md و MAZ_PLANNING_PLAYBOOK.md برای بازه و آزمون من برنامه بساز.
ردیف بودجه را از فایل ماز کنترل کن، ظرفیت واقعی را حساب کن و هر فرض یا کسری را بنویس.
از فرمول ثابت رتبه‌لند فقط برای ظاهر خروجی استفاده کن، نه برای ساعت و تست.
```

## فرمول سادهٔ جدید و برنامهٔ ۱ آبان

فرمول جدید در [`SIMPLE_PLANNING_FORMULA.md`](SIMPLE_PLANNING_FORMULA.md) با زبان معمولی ثبت شده است. اجرای آزمون ۱ آبان در فایل Word چهاربَرگی [`برنامه-فرمول-جدید-۱-آبان-۱۴۰۵.docx`](برنامه%20جدیید/برنامه-فرمول-جدید-۱-آبان-۱۴۰۵.docx) قرار دارد:

- هر جلسهٔ تخصصی ۷۵ دقیقه است؛
- در هر هفته ۳۳ جلسهٔ تخصصی و ۴ ساعت نهایی برنامه‌ریزی شده است؛
- کل برنامهٔ قطعی هر هفته ۴۵ ساعت و ۱۵ دقیقه و زمان جبرانی تا سقف ۵۱ ساعت، ۵ ساعت و ۴۵ دقیقه است؛
- هفتهٔ اول ۲۶۵ تست آموزشی برای مطالب تازه و هفتهٔ دوم ۳۸۰ تست هدفمند برای مطالب مروری دارد؛
- پنجشنبهٔ هفتهٔ دوم بدون مطلب تازه و مخصوص جمع‌بندی است؛
- آزمون جمعه داخل تعداد تست برنامه نیست.

### بازتولید Word فرمول جدید

```bash
python -m venv .venv
.venv/bin/pip install -r requirements-docx.txt
.venv/bin/python scripts/generate_1aban_simple_formula_docx.py
```

مولد، ۱۲ روز، ۷۲ خانهٔ فرم، ۶۶ جلسهٔ تخصصی، ۸ ساعت نهایی، ۶۴۵ تست، چهار صفحهٔ ذخیره‌شده و سالم‌بودن بستهٔ DOCX را کنترل می‌کند.

## برنامهٔ اصلاح‌شدهٔ رتبه‌لند برای ۱ آبان ۱۴۰۵

خروجی استاندارد جدید در پوشهٔ درخواستی [`برنامه جدیید/`](برنامه%20جدیید/) قرار دارد: PDF مستقل پنج‌صفحه‌ای و DOCX چهاربَرگی که فقط متن برنامه را در همان طراحی، جدول‌ها، تصاویر و قالب فایل اصلی جایگزین می‌کند. این برنامه:

- هستهٔ ۴۷ ساعت/۴۹۵ تست هفتگی و ۹۴ ساعت/۹۹۰ تست دوهفته‌ای را حفظ می‌کند؛
- ساعت و تست روزانهٔ اصلی را تغییر نمی‌دهد؛
- تحلیل غلط/سفید/شک‌دار و درستِ نکته‌دار را جایگزین تحلیل عمومی همهٔ گزینه‌ها می‌کند؛
- تست زیستِ لقمهٔ قبلی را در چارچوب ثابت مقدم می‌کند؛
- هفتهٔ دوم را «دوازدهم ـ مرور پایهٔ دهم» معرفی می‌کند؛
- پنجشنبهٔ قبل آزمون را بدون مبحث سنگین جدید نگه می‌دارد؛
- در نسخهٔ PDF، صفحهٔ پنجم را به بودجه، قواعد اجرا و هشدارهای امکان‌پذیری اختصاص می‌دهد.

### بازتولید PDF اصلاح‌شده

```bash
.venv/bin/python scripts/generate_1aban_rankland_corrected.py
```

### بازتولید Word در قالب اصلی

فایل قالب اصلی محلی است و در Git نگهداری نمی‌شود. مولد زیر فقط متن‌های `word/document.xml` را عوض می‌کند و همهٔ اجزای دیگر قالب، از جمله جدول‌ها، سبک‌ها، تصاویر و فونت‌های توکار، را بدون تغییر کپی می‌کند:

```bash
python3 scripts/generate_1aban_rankland_corrected_docx.py \
  --template 'google_drive/برنامه آزمون ۰۱ آبان ۱۴۰۵ (2).docx'
```

اعتبارسنج داخلی، ۱۲ روز، ۵۴ باکس، ۹۴ ساعت، ۹۹۰ تست، چهار صفحهٔ ذخیره‌شده و تغییرنکردن اجزای غیرمتنی OOXML را کنترل می‌کند.

## نمونهٔ اجرایی ترکیبی ۱ آبان ۱۴۰۵

نمونهٔ PDF موجود در `outputs/` با این معماری ساخته شده است:

- بودجه و جدید/مروری: روش ماز؛
- ظرفیت: ۵۸ زنگ فرض‌شده، ۵۲ زنگ قطعی و ۶ زنگ انعطاف؛
- تست زیست: دو روز پس از مطالعه؛
- تعداد تست: ثبت واقعی در زنگ ۷۵دقیقه‌ای، نه عدد ثابت؛
- ظاهر: فرم طلایی و خانه‌بندی شبیه خروجی رتبه‌لند؛
- صفحهٔ پنجم: مقایسهٔ مستقیم با نسخهٔ ۹۴ساعته و ۹۹۰تستی قبلی.

این نمونه شخصی‌سازی‌شده نیست و برای مقایسهٔ معماری ساخته شده است. زمین‌شناسی نیز برای همسانی دامنه با خروجی اصلی چهاردرس حذف شده است.

### بازتولید PDF

```bash
python -m venv .venv
.venv/bin/pip install -r requirements-pdf.txt
.venv/bin/python scripts/generate_1aban_hybrid.py
```

## ورودی‌های ضروری

- تاریخ و سال آزمون یا بازهٔ درخواستی؛
- رشته و وضعیت دهم/یازدهم/دوازدهم/فارغ‌التحصیل؛
- فایل برنامهٔ راهبردی یا بودجهٔ رسمی آزمون؛
- ساعت مدرسه و کلاس‌های ثابت؛
- مباحث قبلاً خوانده‌شده و سطح هر درس؛
- امتحان مدرسه/نهایی و محدودیت‌های فردی.

## خروجی مورد انتظار

در هر دو مسیر:

- بودجهٔ تصویری و صفحات چاپیِ کنترل‌شده؛
- بخش‌های جدید و مروری؛
- جدول روزانهٔ مطالعه، تست، مرور و تحلیل؛
- روز قبل آزمون و روز آزمون؛
- گزارش پوشش، فرض‌ها و کنترل کیفیت.

در مسیر ماز، گزارش ظرفیت/تقاضا/کسری نیز الزامی است. در مسیر رتبه‌لند، جمع دقیق ساعت/تست و گزارش امکان‌پذیری باکس‌ها الزامی است.

## اصل معماری

```text
درخواست فرمول ساده → موتور SIMPLE_PLANNING_FORMULA    → قالب دلخواه یا Word موجود
درخواست رتبه‌لند    → موتور RANKLAND_PLANNING_PLAYBOOK → قالب رتبه‌لند
درخواست ماز          → موتور MAZ_PLANNING_PLAYBOOK      → قالب دلخواه
درخواست ترکیبی       → موتورهای نام‌برده با اعلام منشأ قاعده و بدون اختلاط پنهان
```

فایل‌های منبع PDF و کتاب‌ها به‌دلیل حجم و حقوق انتشار داخل مخزن نگهداری نمی‌شوند. برای هر آزمون، ایجنت باید فایل بودجه و منابع همان درخواست را دریافت و دوباره کنترل کند.
