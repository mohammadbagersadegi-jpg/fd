# 04 - Asset Production

## Pipeline

```
config/animation.json ─┐
                       ├─> tools/asset_pipeline/build_characters.py ─> frames/ + spritesheets/ + previews/ + manifest.json
tools/asset_pipeline/rig.py (poses) ─┘
config/stage.json ────> tools/asset_pipeline/build_stage.py ────────> stage/layers/*.png, props, UI, manifest.json
tools/asset_pipeline/font5x7.py ────────────────────────────────────> fonts/font5x7.json + .js
config/*.json ────────> tools/asset_pipeline/bundle_data.py ────────> game/src/generated/data.js
tools/asset_pipeline/design_sheet.py ───────────────────────────────> artifacts/design-sheet.png
tools/validation/validate_assets.py ────────────────────────────────> reports/asset-validation.json
```

One command rebuilds everything: `python3 tools/asset_pipeline/build_all.py --docs`.

## Sprite rig

`rig.py` is a parametric 2D skeletal rig:

* two-bone IK for arms and legs, fixed bone lengths (11.5+11 / 12.5+12.5 px),
* a torso built from a rotated quad with a shaded back panel, copper lapels, a
  chest emblem and shoulder plates,
* a head authored in 3/4 view with hair spikes, brow, eye, nose, mouth and a rim light,
* copper gauntlets with glow seams and baked electric arcs on flagged poses,
* a scarf whose tails wave based on a per-frame phase value.

Poses are plain functions of the frame index, so adding a frame is adding a
`Pose(...)` entry plus a row in `config/animation.json` (see README §"adding an
animation"). The rig refuses to emit a frame whose artwork leaves the canvas.

## Validation gate

`tools/validation/validate_assets.py` checks 84 frame files and 19 spritesheets:

* every configured frame exists and decodes,
* size equals the configured canvas,
* no frame is fully transparent,
* sheets are exactly `frames * 128` wide,
* grounded animations share a stable feet row and sit within 2 px of the anchor,
* manifests agree with the config,
* artwork touching a canvas edge is reported as a warning (lying-down poses).

Latest run: **0 errors, 3 warnings**. All three are "frame identical to the
previous frame" (VOLT fall #3, RIVET fall #3, RIVET defeated #1): those are
deliberate 2-frame holds at the end of a knockdown, not dropped frames. The
floor poses were lifted 2 px in `rig.py` so no artwork touches the canvas edge.
See `reports/asset-validation.json`.

## Preview and visual QA

`game/assets/characters/volt/previews/` contains one animated GIF per animation
plus `contact_sheet.png`. Visual QA was performed by rendering the contact sheet
and enlarged frames and looking for silhouette drift, limb popping and anchor
jitter; the head was rewritten once (it initially read as a beard) and the
knockdown pose was rebuilt (the first version reused the standing skeleton at
-90°, which produced an unreadable pile).

## Palette rules

* One palette per character, 21 colours for VOLT, exported with hex codes on
  `artifacts/design-sheet.png`.
* Outline `#110E18`, rim light `#6EF0FF` on the shadow side, teal jacket
  `#1C7A72`, copper gauntlets `#B85C2A`, glow `#63F7FF`.
* The stage deliberately avoids those exact teals in the fighting lane so the
  character silhouette stays readable against the wet asphalt.

## Stage art

`build_stage.py` renders five parallax layers procedurally (sky with moon haze,
tileable skyline, tileable facades with neon signs and lit windows, a unique
1800 px street, and an overlay of cables + a low railing). Neon signs are drawn
on a separate layer, Gaussian-blurred and composited back for bloom.

## Originality / licensing

Every pixel is generated by code in this repository from shapes defined here.
No file from Streets of Rage (sprites, palettes, tiles, music, SFX) is included.
The *reference* game is discussed only as technical documentation, and no ROM is
distributed or required.

## Layout deviation from the recommended template

The directive's recommended tree puts character assets at
`assets/characters/electro_fighter/...`. This project ships them at
`game/assets/characters/volt/...` so the browser build has a single asset root
(`game/assets`) and no copy step. Mapping:

| Recommended | Actual |
|---|---|
| `assets/characters/electro_fighter/source/` | `tools/asset_pipeline/rig.py` + `config/animation.json` (the art is code, not per-character source files) |
| `assets/characters/electro_fighter/frames/{idle,walk,...}/` | `game/assets/characters/volt/frames/<anim>/` (12 anims) |
| `assets/characters/electro_fighter/spritesheets/` | `game/assets/characters/volt/spritesheets/` |
| `assets/characters/electro_fighter/previews/` | `game/assets/characters/volt/previews/` |
| `assets/characters/electro_fighter/manifest.json` | `game/assets/characters/volt/manifest.json` |

The enemy (`rivet`) follows the same layout. `game/assets` is the runtime root
served by `tools/serve.js`; there is no duplicate copy of any frame.
